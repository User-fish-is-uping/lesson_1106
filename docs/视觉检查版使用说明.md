# 人员检测检查版 v0.1

本页保留首轮 v0.1 历史交付记录。当前计数版本见 [双向计数集成回传](双向计数集成回传.md)。最新构建脚本默认 vision-check 输出 v0.2 检测版，指定 -Target vision-count 才输出计数版；本页下列 v0.1 大小与哈希仅对应历史固件。

状态：2026-11-06 K210 交叉编译成功；尚未烧录或实板验证。

## 交付与用途

固件：`dist/vision-check/greeter-vision-check-v0.1.bin`，1,740,416 字节。

SHA256：`1C0FB66E014C804C86774D38E4951F61A05CCCF4C972D5BE84CE591488020C70`。

已编入课程 detect.kmodel，无需另外下载模型或用 TF 卡加载模型。
本版本用于检查摄像头、person 检测、LCD 和串口帧数据。没有双向计数、按键控制或语音，屏幕明确显示 VISION ONLY。

## 预期行为（待板上验证）

1. 启动显示 Greeter vision check v0.1，串口输出固件和模型配置。
2. 自动尝试课程支持的 OV9655、OV2640、GC2145 摄像头，串口输出识别型号。
3. 模型成功加载后输出 model ready；屏幕显示视频、青色人员框、黄色 A 线和绿色 B 线。
4. 串口输出 JSONL frame 行：seq、t_ms、valid、truncated、persons 和 dt_ms；坐标遵循接口 v0.2。
5. 相机或 KPU 超时会输出错误、无效帧并停止工作，等待人工检查后重启，避免超时后重新使用仍活动的 DMA。

人员框数量达到 10 时保守标为 truncated。初始方向、实际帧率、检测质量尚未标定。
dt_ms 是连续采集完成的时间间隔。逐帧串口输出会影响运行帧率，特别是多人时，必须记录实测值。
串口还可能包含底层课程驱动的普通文字；回放工具只解析以 `{` 开始且 kind 可识别的 JSON 行。

## 本地编译

在课程根目录，用 PowerShell 7 执行：

```powershell
& '.\lesson_1106\tools\windows\build-vision.ps1'
```

脚本从课程 SDK 复制源文件到 `K210-dev/greeter-sdk`，从课程资料读取模型，再编译。
原始 SDK 和课程例程不改动；修改 `firmware/vision_check/` 后重新运行脚本即可。
`K:` 仅作为 `K210-dev` 的路径别名，避免旧工具链处理中文路径失败。已占用且指向别处时脚本停止。
脚本仅对当前进程增加工具链 DLL 搜索路径，不修改系统或用户 PATH。

Codex 沙箱内 GCC 曾报“无效的系统 DLL 重定位”，本次通过审核在沙箱外完成编译。
详细日志：`build/logs/vision-build.log`。SDK 的 CMake 弃用提示，以及课程代码的未用变量和 qsort 回调 const 类型警告仍存在，编译和链接成功。

## 实板检查顺序

1. 确定实际接板电脑、板卡 V1.1、当前串口号，保留已有启动固件的来源；不要套用历史 COM5。
2. 在 K-Flash_Yahboom 中选择本目录交付的 bin。下载到 Flash 会替换当前上电程序；本轮尚未自动执行下载。按已有课程下载流程操作，下载时关闭占用串口的终端。
3. 下载结束后，用串口终端设置 115200、8N1、无流控，打开后复位板卡，以保留启动日志。保存原始串口文本。
4. 首先保持空画面 5 秒，检查视频是否连续、persons 是否为空。再由一名同学从两条线的一侧缓慢移动至另一侧，并停留、折返。
5. 检查人员框是否跟随身体，确认屏幕左右和实际移动方向；此版本不应出现进出计数或语音。
6. 将日志和实际动作说明交回桌面侧。云端可用这些 frame 行测试 core，但人工进出事件需要另外标注，不能把检测框本身当作正确通行标签。

若没有画面或出现 VISION ERROR，保存从复位开始的全部串口信息，不要反复更换不同板型的固件。

## 本版本资源

| 资源 | 用途 |
|---|---|
| KPU DMA5 | 模型推理 |
| SPI0、SS3、DMA0 | LCD |
| GPIOHS0、GPIOHS1 | LCD 复位与数据/命令 |
| IO36–39 | LCD |
| IO40–47、DVP 中断 | 摄像头 |
| PLL0 800 MHz、PLL1 400 MHz | 沿用课程系统配置；初始化后不动态切换 |
| UARTHS 115200 | 调试日志 |

TF、扬声器、按键和 IMU 尚未启用。后续音频不能直接沿用原例程 DMA5；按键也须避开 LCD 占用的 GPIOHS。
