## 3. C 标准与冻结方式

接受 C99、无动态内存、无 SDK 依赖、单线程主循环调用。现有 SDK 的 cmake/compile-flags.cmake 使用 `-std=gnu11`，可编译该 C99 子集，板端最终仍需实际交叉编译。公开类型使用 stdint.h、stdbool.h 等标准头文件。请先交 greeter.h、audio_queue.h 及必要的公开语义说明，桌面按提交号审阅后冻结；当前是语义 v0.2，尚无已冻结的 C 头文件。

## 4. 模型输出与适配约定

已核对课程 `高级实验例程2/7.物体检测/代码/object_detection/main.c`：20 类标签中 person 为零基索引 14；region_layer_init(...,320,240)；threshold=0.5，NMS=0.2。region_layer 的输出已进行阈值和 NMS 处理，桌面仍会显式筛选 person 及 score>0.50。

输出是 320×240 图像坐标。320×256 是 AI 缓冲相关尺寸，不能作为输出框归一化分母。桌面将修正原例程可能先转无符号数的边界处理，在浮点阶段裁剪后 x/319.0f、y/239.0f，传入 0..1 框。默认取底边中心，X 为横向主轴。实际相机镜像与 LCD 朝向尚未实测；桌面保证画面判断线和 core 输入一致，reverse_direction 供现场切换。没有真实检测日志可提供，不能拿合成输入冒充。

适配流程（约定伪代码，不是已完成实现）：

```text
完成一次采集与推理 -> 记录 sequence_id 和单调 now_ms
失败 -> valid=false
成功 -> NMS/阈值筛选 -> 收集 person 类框 -> 浮点裁剪/归一化
列表容量不确定或溢出 -> truncated=true
成功但无人 -> valid=true, person_count=0
每帧只调用一次 greeter_update
```

桌面会在写入检测列表之前检查容量，不能先让课程固定数组溢出后才标记 truncated。

## 5. 双线严格程度

接受必须观察到中间区域，首版不开启跨帧推测穿越。直接 A 外侧跳到 B 外侧且没有中间证据时不计数，清理旧候选，由当前侧重新积累稳定起点。中间证据也必须通过位置关联；不能因为曾在中间出现过，就允许之后任意换人跳转。

具体区域和重置规则已补充到接口 v0.2。请把中间证据、直接跳跃、缓冲带停留、快速折返、短时空检测、多人重新建立起点列为确定性测试。位置关联速度上限由配置提供，首轮测试可用显式测试值，但不能宣称为实板标定值。严格策略可能漏掉低帧率下的快速通行，后续用真实日志调整机位、间距和阈值。

## 6. 语音、静音与清零

接受每事件最多启动两次（首次加一次重试）；BUSY 不计次数。首轮固定 STARTED/BUSY/FAILED 三种启动结果，空闲查询与异步播放失败另外报告。成功启动就消费队首，之后异步出错只记录，不重新排队，避免重复欢迎。

静音清空待播项，期间新事件不入队；恢复不补播。清零或实际切换方向清理候选与待播队列；当前一句允许播完。静音也允许当前一句播完，避免首轮强制中断带来的 DMA 清理复杂度。切换方向不清历史计数。event_id、去重水位和累计错误数不因清队列重置。

原始 bsp_play_wav 仅返回 0/-1，没有规范的 BUSY 返回，不能声称已经满足接口。桌面将增加状态包装和失败资源回收。视觉 KPU 和课程音频同时占用 DMA5，集成前必须重新分配；云端无需感知具体通道。

## 7. 编号与时间

同意 event_id、sequence_id、now_ms 使用 uint64_t；event_id 每次上电从初始状态递增，清零计数不重置，重启重新初始化。桌面可提供同一单调毫秒时钟，并让帧、事件和音频日志共享。

本地 SDK 的 sysctl_get_time_us 使用 `cycle*1000000/frequency`，乘法存在长时间运行溢出风险。桌面会在时钟初始化完成后保持 CPU 频率固定，并用周期差及商余法安全换算：`ms=(cycles/hz)*1000+((cycles%hz)*1000)/hz`，避免原始微秒实现的乘法风险。不把 RTC/电脑墙钟传给 core。实际计时适配仍待实现和验证。
