# 双向客流统计与语音迎宾系统两人开发计划

计划基准为 2026 年 11 月 6 日，北京时间。日期依据老师第三节课件第 104、105 页。下面是建议执行安排，后续按真实进度更新。

## 1. 两人先理解整条流程

系统每次拍摄画面，KPU 模型检测其中的人员。程序获得人员框和时间，把位置变化交给进出状态机。确认一次完整通行后生成一个进入或离开事件，同时更新计数。语音调度模块把这个事件交给扬声器，LCD 显示判断过程。

```text
摄像头取图
    ↓
KPU 检测 person，输出位置和分数
    ↓
检测结果适配为统一的帧数据
    ↓
单人关联、双线判断、停留和折返处理
    ↓
生成唯一编号的 ENTER 或 EXIT 事件
    ├── 更新进出次数、LCD 和串口日志
    └── 进入语音队列 → 空闲时播放对应 WAV
```

欢迎语只由已确认的进入事件触发。送别语只由已确认的离开事件触发。方向的判断依赖连续帧，摄像头应覆盖通道的两侧。相机朝向和 LCD 镜像在现场一起校准。

你们需要理解三个边界。检测模型回答画面中人员的位置，状态机回答是否完成一次穿越，语音模块回答何时播放哪一句。这三块可以分别测试，再逐步组合。

## 2. 报题与必交功能

建议题目为《基于 K210 的双向客流统计与语音迎宾系统》。

应用场景是商店单通道入口的欢迎、送别和客流统计。首版采用一个人依次通过的演示范围，使用课程现成的 person 检测模型。

| 项目 | 首版完成标准 |
|---|---|
| AI 检测 | 实板可持续给出人员框，记录检测分数和帧间隔 |
| 双向判断 | A 到 B 生成进入事件，B 到 A 生成离开事件，支持方向反转配置 |
| 防重复 | 同一人停留或在边线附近晃动，进出次数保持正确 |
| 折返 | 未完成穿越就退回原侧，撤销候选事件 |
| 遮挡处理 | 短时漏检在有限时间内保留候选，长时间丢失后重新建立起点 |
| 多人提示 | 同时多人的片段显示需复核，暂停该片段自动计数 |
| 语音 | 进入播放欢迎语，离开播放送别语，播放期间保持视觉检测 |
| 屏幕 | 显示框、两条线、状态、进出次数、语音或 SD 状态 |
| 操作 | 按键清零与方向设置，清零动作同步清理未完成候选与待播队列 |
| 可诊断 | 串口可区分视觉、逻辑、音频错误 |

课程创新点集中在双线方向判定、异常通行处理和视觉与语音的协同。开题用一个正常动作和一个折返动作解释状态机，结题用对照测试说明改进。

首版以后再考虑 Wi-Fi 上报、板上录制欢迎语、多页面 LVGL、历史日志和更复杂的多人跟踪。

## 3. 两个人与两边 Codex 的分工

默认 A 是本聊天的用户，使用桌面 Codex，B 是同学，使用云端 Codex。两人的工作都包含设计、实现验证和报告。

| 工作 | A 与桌面 Codex | B 与云端 Codex |
|---|---|---|
| 工程集成 | 主责，搭建 K210 工程，形成唯一板端集成版本 | 阅读接口，按约定交付纯 C 代码 |
| AI 与驱动 | 摄像头、KPU、人员框适配、LCD、TF、I2S | 使用统一帧数据作为输入 |
| 逻辑 | 将真实帧喂给状态机，回传串口日志 | 主责，方向、防重、折返、丢失与多人处理 |
| 语音 | 主责播放器、采样格式、DMA 和资源释放 | 主责队列、顺序、过期事件与重复事件处理 |
| 测试 | 主责烧录、摆位、真实通行动作、实板记录 | 主责合成序列测试、日志回放和错误分析 |
| 答辩 | 主责硬件、AI 部署与端到端演示说明 | 主责状态机、测试结果与误差分析 |

Codex 可以承担代码编写、测试执行、交叉编译、审查和错误修复。你们负责接线、插拔、放置板卡、插卡、播放试听和现场通行，并将现象和日志带回来。实际接板电脑如果与桌面 Codex 工作电脑不同，采用固件和日志文件交接。

两边的聊天上下文和本地文件分别独立。通过共享仓库、任务书、接口文件和交接记录传递状态。仓库连接成功后，云端 Codex 以同学账户可访问的仓库为工作来源。

## 4. 让同学的云端 Codex 开始工作的步骤

1. 两人各自读 README 和本计划前 3 节，确认首版范围与责任人。
2. 建立一个专用于本项目的 GitHub 仓库，例如 k210-greeter。将本目录内容上传，确认 README、AGENTS 和 docs 都在仓库根下。
3. 由仓库所有者邀请另一位同学。两人确认各自账户有相应访问权限。
4. B 在云端 Codex 连接该仓库，按界面选择或创建云端环境。官方当前流程支持选择 GitHub 仓库、准备环境、检查后开始任务。
5. B 将 docs/云端Codex任务书.md 的第一轮提示词发送给自己的 Codex。它读取仓库文件，完成 core 和 host tests。
6. B 提供分支、提交号或 PR 链接。A 将该版本同步到本地，由桌面 Codex 审查和交叉编译后合入。
7. 没有 Git 经验时，B 也可以导出改动文件包交接，但云端首次运行仍需要一个它能访问的代码工作环境。上传聊天附件能否执行完整开发，以 B 当前产品界面支持为准。

共享仓库先放项目文档和新代码。SDK、交叉编译器和烧录软件由桌面侧保持本地依赖，避免把数百 MB 的课程工具链一起上传。需要复用的课程源码由桌面 Codex挑选、保留署名并在集成阶段加入项目。

官方来源为 https://learn.chatgpt.com/docs/cloud 。账号连接和仓库访问由各自账户完成。此计划未替两人建立远程仓库或账户连接。

## 5. 开发步骤与每步交付

### M0 环境与接口

A 确认使用 V1.1 板卡、实际接板电脑、USB 线、TF 卡与读卡器。重新记录当前 COM 口，保留现有可恢复固件的文件来源和版本。桌面 Codex 复核构建命令，保持原始课程目录完整。

B 建立可运行 C 代码和 CMake 的云端工作环境。云端 Codex 根据接口约定产出第一个公开头文件，桌面 Codex核对后冻结为 v0.1。

交付是环境记录和已审阅的接口头文件。上级目录的 hello_world 仅证明本地工具链曾编译通过，项目的硬件链路需另行确认。

### M1 两条独立硬件链路

A 与桌面 Codex 分别完成视觉版和音频版固件。视觉版显示 person 框并打印检测信息。音频版按键播放两段真实 WAV，验证音量、语速、重复播放和文件读取。

建议音频统一为标准 PCM WAV、22050 Hz、16 位、双声道，每句尽量短。先按课程播放器的实际配置统一格式，后续若改采样率由桌面 Codex一起改代码和素材。课程播放器当前写死了 22050 Hz，不能只看 WAV 扩展名判断是否适配。

B 同时在云端完成基础状态机和正常、反向、停留、折返的测试。

交付是两个可编译的板端检查版本、两份板上测试记录，以及状态机第一版主机测试结果。

### M2 独立逻辑可回放

B 的云端 Codex 完成短时漏检、长时丢失、多人、轨迹跳变和计时边界测试。使用每帧的检测框序列回放逻辑，产生 ENTER/EXIT 事件及其时间。

A 的桌面 Codex 将真实检测输出适配为约定格式，采集短段串口日志供 B 回放。接口保持独立于 region_layer_t 和 KPU 句柄。

交付是可重复运行的主机测试与回放命令，并区分合成测试和真实检测日志。阈值先用建议值，再按现场帧率调节。

### M3 视觉、计数与 LCD

A 将 B 的 core 代码集成到 K210 工程。第一轮先让 LCD 与串口正确显示进出事件，检查显示方向与实际进入方向相符。暂时把扬声器开关设为静音，定位计数问题。

交付是单人正常进入、离开、停留和折返四类实测记录。B 根据真实日志修复算法，A保持板端适配。

### M4 语音与检测同时运行

A 集成 I2S 播放，保留 KPU DMA 通道 5，为音频分配经核查空闲的另一 DMA 通道，统一时钟与中断资源。

B 的队列按 event_id 防重复，保持进入/离开语音的顺序。队列过期或满时记录原因，计数结果保留。音频播放失败时给出屏幕和串口提示，视觉流程继续运行。

课程播放器有大块动态缓冲和在 DMA 回调中进行文件操作的实现。桌面 Codex 需要审查缓冲长度、末块长度、读卡位置和资源释放。目标是把耗时读卡放到主循环或受控服务中，DMA 回调只做必要的标记与切换。并发是否稳定由实板持续运行验证。

交付是播放欢迎语期间再次发生通行，系统仍有连续检测日志，下一条语音按顺序执行。

### M5 现场验证与演示冻结

完成下面的验证表，固定相机位置、两线位置、音频文件和固件版本。将固件、音频、烧录步骤和已知范围打成发布包。A、B 分别准备自己负责部分的解释。

交付是可复现演示、真实测试数据、回退版本和分工说明。编译成功、电脑测试通过和实板通过分别记录。

## 7. 测试与验收

### 电脑上的逻辑测试

云端运行合成检测序列，验证精确的事件与计数。覆盖 A→B、B→A、初见就在中间、长期停留、边线抖动、未完成折返、完成后返回、短时漏检、长时丢失、多人和轨迹跳变。队列覆盖重复 ID、忙时到达、满队列、过期、播放失败和静音。

这些测试证明逻辑在输入给定时的表现。实物检测效果由下面的硬件测试补齐。

### 板上测试建议数量

| 情况 | 建议轮次 | 预期 |
|---|---|---|
| 进入 | 20 次 | 每次恰好一个 ENTER，一句欢迎语 |
| 离开 | 20 次 | 每次恰好一个 EXIT，一句送别语 |
| 门口停留与边线小幅晃动 | 共 10 次 | 完整穿越之前计数保持不变 |
| 进入一半折返 | 10 次 | 无完整通行事件 |
| 连续完成进入再离开 | 5 轮 | 每轮一进一出，语音顺序正确 |
| 两人同时出现 | 5 次 | 显示需复核，离开歧义状态后恢复 |
| 拔掉 TF 卡后启动 | 1 次 | 提示音频不可用，人员检测仍可观察 |
| 语音播放期间继续经过 | 5 次 | 继续记录检测与事件，排队行为可解释 |
| 固定机位持续运行 | 建议 10 分钟 | 记录卡顿、读卡和内存异常 |

测试记录采用人工标注的实际通行时间窗，一对一匹配机器事件，分别统计正确方向、漏计、重复、错方向。语音另外统计顺序错误、漏播和从确认到开始播放的延迟。连续播放中的排队延迟单列，避免混成检测延迟。

对照实验可在相同的真实检测序列上比较单线触发和双线状态机。保留原始输入及人工标注，明确哪些结果来自电脑回放、哪些来自实时板上运行。表中的次数是建议计划，实际结果需测量后填写。

### 验收的五分钟操作顺序

先展示硬件和主界面，解释两线与方向。A 正向通过一次，B 指出欢迎语和进入计数。再反向一次，展示送别语。随后演示停留和半程折返。最后展示一张真实测试结果表，说明适用范围及多人片段的复核策略。

## 8. 常见问题与处理路径

| 现象 | 先看什么 | 对应负责人 |
|---|---|---|
| 烧录后无画面 | 摄像头型号、串口初始化日志、固件文件和供电 | A 与桌面 Codex |
| 有框但方向错 | 实际画面坐标、镜像、reverse_direction | A 提供视频或日志，B 检查状态机 |
| 人一直站着却重复播 | 事件是否重复、event_id 与原侧更新 | B 查逻辑，A 查事件转发 |
| 播放时画面卡住 | DMA、回调读卡、缓冲与帧间隔 | A 与桌面 Codex |
| 没声音或声音速度异常 | PCM 格式、22050 Hz 配置、声道和 TF 路径 | A 与桌面 Codex |
| 云端测试能跑但板端编译错 | SDK 类型、编译标准、头文件和编译器警告 | A 给错误日志，B 修 core 可移植性 |
| 实际帧率太低 | 两线距离、通行速度、检测分辨率与模型耗时 | A 测量，双方调整范围与阈值 |

## 9. 首轮你们实际要做的事情

A 准备板卡、数据线、TF 卡和读卡器，确认实物连接在哪台电脑上。将本目录保留在桌面 Codex 可访问的位置。B 将本目录放进自己的云端可访问仓库，并发送任务书里的第一轮提示词。两人各自记录自己完成了哪些检查。

后续开发按 M0、M1 顺序推进。桌面侧先形成可观察的检测与播放版本，云端侧同时实现纯 C 状态机。每轮代码由对应 Codex 完成，再由另一侧检查接口和证据。
