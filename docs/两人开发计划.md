# 项目计划

## 项目目标

面向商店单通道入口，使用现有 KPU 人员检测模型，实现双向客流统计、欢迎与送别语音、LCD 状态显示。人员检测提供框位置，双线状态机确认通行，语音队列按事件顺序调度播放。

当前范围限定为单人依次通过。多人同时出现、检测列表截断或轨迹异常时暂停该片段自动计数，并重新建立稳定起点。Wi-Fi、板上录音、复杂页面与多人跟踪不属于当前版本范围。

## 开发分工

| 模块 | 责任 |
|---|---|
| 核心逻辑 | 通行状态机、语音队列、公共头文件、主机测试、日志回放 |
| 固件集成 | 摄像头、KPU 输出适配、LCD、按键、TF、I2S、构建与烧录 |
| 联合验证 | 配置标定、真实通行测试、异常复现、版本与数据记录 |

核心逻辑位于 `core/`，保持标准 C99、无动态内存和 SDK 依赖。固件通过公共接口调用，不另行维护一套通行判定逻辑。

## 开发阶段

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| 环境与接口 | 核实工具链、板卡、模型与公共类型 | 构建入口明确，接口按提交版本审阅 |
| 独立链路 | 人员检测、音频播放分别验证 | 有检测输出与播放记录，错误可诊断 |
| 核心逻辑 | 方向判定、异常处理、语音调度 | 确定性主机测试通过 |
| 视觉计数 | 检测结果接入 core，显示事件与计数 | 进入、离开、停留和折返实测可复现 |
| 音频集成 | 播放器包装、队列接入、资源协调 | 播放期间保持检测，队列顺序正确 |
| 验收 | 固定机位与参数，记录结果并打包 | 固件、配置、音频、日志及运行说明齐全 |

## 验证计划

| 场景 | 建议次数 | 预期 |
|---|---|---|
| 正向通行 | 20 次 | 每次一个 ENTER，对应欢迎语 |
| 反向通行 | 20 次 | 每次一个 EXIT，对应送别语 |
| 停留与边线晃动 | 10 次 | 无完整通行则不计数 |
| 半程折返 | 10 次 | 不产生完整通行事件 |
| 完成进入后返回 | 5 轮 | 每轮一次进入、一次离开 |
| 多人同时出现 | 5 次 | 提示复核，重新建立起点 |
| 语音播放期间通行 | 5 次 | 检测持续运行，事件按序处理 |
| 固定机位持续运行 | 10 分钟 | 记录卡顿、读卡及资源异常 |

次数为测试计划，结果以实测填写。人工标注与机器事件按时间窗匹配，分别记录正确方向、漏计、重复、错方向和语音延迟。
