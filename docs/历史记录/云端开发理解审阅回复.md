## 2. 对第 4 节边界规则的确认

接受所列默认行为：重复/倒退序号忽略；相同时间新帧不累计稳定时间；端点连续稳定与候选保留分离；各时间边界等号；离开原外侧才开始穿越超时；二维关联；非法输入拒绝；明确配置校验；有序事件去重水位；以事件时间计算音频等待；启动结果按事件 ID 校验；分类统计和整数溢出保护。

补齐以下具体语义，写进头文件注释和回归测试：

1. **序号先于时间校验。** 重复或倒退序号直接忽略，不更新任何轨迹或逻辑时钟。对序号递增但时间倒退的新帧，消费这个新序号、清除候选并报告异常，保留最后接受时间作为水位；本帧不得作为起点。后续序号递增但时间仍低于水位时继续拒绝，直到时间达到或超过水位，才允许重新建立起点。重启通过 init 显式恢复，不自动把时钟回退当成重启。
2. **无新帧也算观测中断。** 若两次有效人员观测间隔大于 lost_grace_ms，即使中间没有送入空帧，也不能沿用旧轨迹；清理后当前合法单人帧可开始积累新起点。否则程序卡顿可能被误认为连续稳定。间隔等于 grace 仍按既定规则允许关联。
3. **二维关联用两次人员观测的时间差。** 中间空帧不刷新最后人员位置或其时间。允许距离的基础容差及速度上限必须有限且非负，测试参数和未实测的默认参数分别说明，不宣称已标定。
4. **音频时钟异常不破坏队列。** 未来时间事件拒绝入队并计原因，不提升去重水位；服务时间倒退则拒绝本轮调度、不消费队首、不增加启动尝试次数，保留时间水位，待时钟追上后恢复。只对有效的新事件执行“静音、队满、过期等丢弃仍提升 ID 水位”。真实板端发生时钟异常时桌面记录错误并停止产生通行音频，调查后再恢复。
5. **主循环调度单次化。** 每轮最多发起一次启动；FAILED 后即使仍是同一队首也必须等下一次服务。STARTED、BUSY、FAILED 仅报告真实播放器调用结果；队首 ID 不匹配不消费队列。core 不保证恶意调用方多次调用等价于一次主循环，桌面遵守该调用约定。
6. **计数与事件一致。** 事件 ID 耗尽时拒绝该次通行提交并报告，不产生没有唯一事件的计数增长。计数溢出按提案饱和并诊断。正常量级不会触及这些边界，但测试须覆盖。

中间区域要求严格正宽度，继续采用严格 person 置信度筛选。默认阈值仍是起点值，头文件中应给出完整配置关系，不得临时删除异常检查来通过测试。
