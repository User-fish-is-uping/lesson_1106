# 发给同学云端 Codex 的任务书

同学先把本目录放入其云端 Codex 能访问的代码仓库，建立或选择该仓库的云端环境。然后将下面第一轮提示词整体发送给云端 Codex。

## 第一轮提示词

```text
我们是两人课程项目，题目是《基于 K210 的双向客流统计与语音迎宾系统》。另一位同学使用桌面 Codex 接入真实 K210 板卡，负责 KPU 人员检测、LCD、TF 卡、I2S 播放与固件集成。你负责可移植的 C 逻辑。

请先阅读 README.md、AGENTS.md、docs/两人开发计划.md 和 docs/接口约定.md，直接实现首轮任务。现阶段从合成检测框输入做状态机，不需要实际板卡和神经网络模型。

实现 core/greeter.h、core/greeter.c、core/audio_queue.h、core/audio_queue.c、tests 和一个可在当前主机执行的 CMakeLists.txt。公共头文件依照接口约定，使用标准 C，状态由调用方持有，时间由外部传入。头文件先明确结构与函数，再实现和测试。

状态机需要覆盖单人双向完整穿越、第一次出现在中间、长期停留、边线抖动、未完成穿越折返、完成一次后直接反向返回、短时漏检、长时丢失、多人、轨迹跳变、无效帧、重复帧号、时间倒退和方向反转。进入与离开都要对称测试。

一次完成的通行产生一个带递增 event_id 的 ENTER 或 EXIT 事件，并在 core 更新计数。停留期间保持计数。歧义后重新建立外侧起点。清零计数保持事件编号递增。

音频队列容量先设 4，按事件顺序保存，按 ID 去重。实现队首查看、成功启动后消费、过期清理、容量满统计和失败处理。忙时保留待播项，模拟测试有界失败重试及继续处理后续项。所有计数保持独立于音频是否成功。

主机测试使用确定性的毫秒时间和规范化检测框，测试要检查实际事件序列和计数结果。配置边界与非法输入也需要覆盖。请真实运行构建与测试，修复失败。

交付时列出已实现功能、公共头文件接口、实际测试命令与结果、已知限制、变更文件清单。将交接条目写入 docs/交接与实测记录.md。说明这些结果是主机模拟测试，K210 交叉编译和实板验证由桌面侧执行。

首轮以 core/、tests/、tools/host/、主机 CMakeLists.txt 为工作范围。硬件资源与 firmware/ 由桌面 Codex负责。必要的接口改动请列明并更新版本，方便桌面侧审阅后接入。
```

## 第二轮提示词

第一次交付并完成接口核对后，使用以下任务。

```text
第一轮 core 已交给桌面侧核对。请基于当前接口补充 tools/host/ 日志回放工具，读取接口约定的 frame JSONL，将数据喂给同一份 C 状态机，输出事件与计数。保留原始输入时间，报告异常输入行号。回放工具需要复用 C 实现，避免另外写一套独立的 Python 计数算法。

加入合成日志作为示例数据，并清楚标记为 synthetic。真实日志到达后，将真实输入和手工标注分别保存，在相同输入上对照单线触发基线与当前双线状态机，分别报告漏计、重复和错方向。没有真实数据时只交付工具与合成测试。

补充语音播放模拟，验证忙时到达、播放完成、静音、文件失败、队列满和过期情况。输出交接记录和可复现命令。
```

## 第三轮按真实日志修复

桌面侧提供实际检测 JSONL、固件配置与人工标注后，将文件提交到共享仓库。B 给云端 Codex 描述实际动作和期待事件，要求它先复现，再修复，再用同一日志和已有测试验证。

每轮交付保存分支、提交号和测试命令。若当前环境没有 C 编译器或 CMake，先使用环境支持的安装方式准备依赖，或准确说明限制及已完成内容。

云端首轮的验证入口建议为以下形式，由其实现后确认实际命令。

```bash
cmake -S . -B build/host
cmake --build build/host
ctest --test-dir build/host --output-on-failure
```

## 同学交回桌面侧的最少信息

- 仓库地址、分支、提交号或 PR 链接。
- 变更文件清单与接口版本。
- 实际执行的构建、测试和回放命令。
- 哪些是合成数据验证，哪些是实际检测日志回放。
- 已知缺陷和下一轮需要桌面提供的信息。

桌面侧将对交回的文件检查接口和可移植性，再做 K210 编译。实物上的方向、声道、屏幕和相机问题由实际板卡结果决定。
