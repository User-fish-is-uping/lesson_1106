# 开发与集成流程

## 仓库与分支

仓库：`https://github.com/User-fish-is-uping/lesson_1106`。

`cloud/core` 维护核心模块与主机工具，`desktop/firmware` 用于板端集成。公共头文件由核心模块维护方更新，固件维护方审阅；接口变更需列出字段、签名和行为差异，并记录对应提交 SHA。

仓库使用根目录结构，不额外嵌套项目目录。根 CMakeLists.txt 用于主机构建，固件构建入口应独立放置，避免覆盖主机配置。

## 集成顺序

1. 核对 `core/greeter.h`、`core/audio_queue.h` 与接口版本。
2. 运行主机测试，将两个 core C 文件加入固件目标。
3. 独立运行人员检测，确认 person 标签、坐标和帧间隔。
4. 将实际检测结果适配为统一帧，先以静音方式验证计数与 LCD。
5. 独立验证 TF 与 WAV 播放，统一采样率、声道和位深。
6. 接入音频队列，核查 DMA、SPI、GPIOHS、中断及缓冲分配。
7. 用真实日志复现异常，修复后重复相同输入与相关测试。
8. 保存固件、配置、音频、SHA256、烧录步骤和验证记录。

课程人员检测与音频例程均使用过 DMA5，集成时需统一资源分配，不能直接拼接各自的初始化代码。模型来源和课程源码署名应保留。

## 变更记录

每次交付记录：分支与完整 SHA、接口版本、文件列表、构建与测试命令、输入数据、结果、未解决问题。主机测试、交叉编译、日志回放与实板结果分别标注。

板端反馈应附固件 SHA256、源码提交、板卡与摄像头型号、实际串口、相机方向、完整参数、音频格式、人工动作时间窗和原始日志。保留未触发事件的帧，避免只截取事件行。

## 仓库访问排查

浏览器访问与开发进程使用的代理、身份和网络环境可能不同。先在运行开发命令的同一终端执行：

```sh
git ls-remote --symref https://github.com/User-fish-is-uping/lesson_1106.git HEAD
```

读取 `cloud/core` 可使用：

```sh
git clone --branch cloud/core https://github.com/User-fish-is-uping/lesson_1106.git
```

截至 2026-11-06 的远端检查，仅发现 `cloud/core`，默认分支也是该分支；指定不存在的 `main` 会失败。后续以 `ls-remote` 的实际输出为准。

- `Could not resolve host`、连接超时或代理连接失败：检查开发进程的网络、代理与沙箱授权。
- `Remote branch main not found`：检查实际分支，不要默认使用 main。
- `Repository not found` 或 HTTP 401/403：核对完整地址、仓库可见性及当前 Git 身份；公开读取与推送权限分别验证。
- `Permission denied (publickey)`：正在使用 SSH，需配置正确 SSH 身份或改用仓库 HTTPS 地址。

公开仓库允许读取，推送仍需协作者权限与有效认证。浏览器已登录不代表终端已完成认证。诊断时保留命令与报错，不输出 Token、密码或认证头。
