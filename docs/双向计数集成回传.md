## 实现内容

- 共用已有摄像头、KPU 和 LCD 链路；新增 firmware/vision_count/counting_app.c 调用同一份 core。
- 每个真实推理结果只送入一次 greeter_update；以采集完成时刻 observed_ms 作为 frame/event 时间。
- LCD 读取 snapshot 显示 IN、OUT、状态、人数和错误码，固件不重复累加计数。判断线位置从同一配置计算。
- 同一组传给 core 的 float 字段使用 %.9g 输出 frame JSONL；event 日志包含唯一 ID、观测时间、方向及累计数，state 日志记录状态与错误码。
- 两个 core C 文件均已纳入 K210 构建并使用 -fno-fast-math；实例静态分配，不在中断调用 core。
- 音频队列初始化后固定静音。确认事件仍调用 audio_queue_push，传入当前 service_ms；日志标为 muted，不操作 TF/I2S，也不声称真实语音已完成。
- 无效采集/推理会送入 valid=false、清理候选并停止本轮诊断程序；人数超容量在读取数组前拒绝，非法分数不输出 NaN/Inf JSON。

## 完整固定配置

以下为本版使用的 greeter_default_config；参数尚未实板标定。

```json
{
  "axis": "X",
  "line_a": 0.35,
  "line_b": 0.65,
  "hysteresis": 0.03,
  "confidence_threshold": 0.5,
  "association_tolerance": 0.05,
  "max_speed_per_s": 2.0,
  "outer_stable_ms": 150,
  "lost_grace_ms": 350,
  "traversal_timeout_ms": 5000,
  "reverse_direction": false
}
```

`firmware/vision_count/config.json` 是配置的回放副本，不是板端运行时读取的文件。适配层测试逐字段校验它与实际初始化配置相同。修改参数须修改 counting_app_init 的赋值、同步该副本并重新测试和编译；只改 JSON 不会改变固件。

启动 config 行用 %.9g 输出实际 float 值，例如 0.35 可能显示为 0.349999994，属于单精度表示，回放时优先使用该行提取的配置。

其他参数：person 类 14；输出 320×240；x/319、y/239 归一化；底边中心参考点；模型 NMS=0.2；有效 score 严格大于 0.5；容量 10，达到容量保守标歧义。队列容量 4、等待上限 5000 ms、muted=true、audio_enabled=false。串口 115200、8N1、无流控；KPU DMA5、LCD DMA0，沿用课程 PLL0=800 MHz、PLL1=400 MHz 设置。相机与 KPU 各 2000 ms 等待超时后报错停止。

## 实板测试与回传

固件路径：`dist/vision-count/greeter-count-v0.2.bin`，模型已内置。附 config.json、manifest.json、SHA256SUMS.txt。本轮没有自动烧录，烧录 Flash 会替换现有上电程序。

1. 记录实际接板电脑、COM、V1.1 板卡，下载指定 bin。串口设置 115200、8N1、无流控，开始保存原始文本后复位，确保保留 boot/config/camera/model 行。
2. 固定机位，一人依次通过。默认屏幕黄色 A 线至绿色 B 线为进入；若显示方向与实体通道相反，先记录，不要自行交换原始日志坐标。
3. 每次完整通行先在起点外侧停留约 0.5 秒，缓慢经过中间，抵达另一侧再停留约 0.5 秒。屏幕明确显示 MUTED，本版没有声音。
4. 至少记录下面四类动作的时间窗与实际屏幕结果。异常时保留整个过程，不只保存 event 行。

| 动作 | 预期变化 | 人工记录 |
|---|---|---|
| 进入：A 外侧→中间→B 外侧 | IN +1，OUT 不变 | 开始/结束 t_ms、实际计数、是否误计或漏计 |
| 离开：B 外侧→中间→A 外侧 | OUT +1，IN 不变 | 同上 |
| 停留：原侧站立并轻微晃动 | IN/OUT 均不变 | 停留时间窗、人员框是否丢失 |
| 折返：A 外侧→中间→返回 A 外侧 | IN/OUT 均不变 | 是否曾到达另一外侧、实际结果 |

每个动作初测 3 次，分别记录。每次复位作为独立日志文件，时间以该次 boot 起算。记录机位、照明、摄像头型号、屏幕朝向与是否发生复位。实际帧间隔可能大于 350 ms，届时 core 会保守重建起点；必须先用原始 dt_ms 定位，不能直接宣称算法失效或擅自放宽参数。

课程驱动启动阶段含非 JSON 文本。原始 serial.txt 必须完整保留，可另提取回放文件：

```powershell
python .\tools\windows\extract-counter-log.py .\serial.txt .\capture-session-01
python .\tools\host\replay.py .\capture-session-01\capture.jsonl --library .\build\host\libgreeter_replay.dll --config .\capture-session-01\config.json
```

提取工具不修改原始文本，保留原始浮点数字；遇到坏 JSON 或混合多次复位时拒绝，不静默删掉错误帧。源代码、manifest、完整原始日志、提取后的 JSONL/config，以及四类人工动作记录一并交给云端。当前不能提供真实 frame/event 数据，因为尚未接板。
