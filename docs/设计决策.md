# 设计决策

## 平台与模型

采用 Yahboom YB-DKA01 V1.1 和课程 C SDK。课程物体检测例程的 20 类标签中，person 零基索引为 14；region_layer 输出按 320×240 处理，320×256 为相关 AI 缓冲尺寸，不作框坐标归一化分母。

框在浮点阶段裁剪后分别除以 319.0f、239.0f，筛选 person 且 score>0.50。模型标签和坐标依据源码核对，实体镜像与显示方向仍需现场标定。

## 通行判定

必须观察到稳定起点之后的有效中间区域，才允许确认另一侧终点。无中间证据的直接跨区不计数；中间证据不能绕过位置关联。此规则优先避免换人、低帧率跳变导致的错误事件，但可能漏掉过快通行，需结合机位和帧率调参。

## 语音调度

播放器启动结果区分 STARTED、BUSY、FAILED。每事件最多两次实际启动尝试；BUSY 不占次数。STARTED 后消费事件，异步错误只记录，不重新入队。静音、清零和方向切换清除待播，已开始播放的一句允许完成。

## 可移植性与时钟

核心模块使用 C99、无动态分配和 SDK 依赖，由单线程主循环调用。帧号、事件号和时间为 uint64_t；使用统一单调毫秒时钟。

板端应核查周期计数换算的乘法溢出风险。固定 CPU 频率后可用商余法换算毫秒：`ms=(cycles/hz)*1000+((cycles%hz)*1000)/hz`，并验证实际时钟实现。

## 验证边界

源码检查只能证明已阅读相关实现。主机测试验证给定输入下的规则，交叉编译验证目标工具链兼容性，实板测试验证摄像头、音频、时序和实际通行效果。四类证据分别记录，不互相替代。
