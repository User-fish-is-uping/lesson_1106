# 计数诊断版 v0.3

用户实测 v0.2：N:1、E:0，但保持 WAIT_ORIGIN，IN/OUT 均为 0。目前没有原始帧日志，不能确认根因。

源码检查发现：起点要求参考点严格处于外侧并保持稳定；两次人员观测间隔超过 350 ms 时会清轨迹，这条路径不设置错误码，因此 E:0 并不能排除帧间隔过长。原 LCD 文字函数逐个亮像素设置窗口并发送 SPI/DMA，可能增加帧耗时，但影响程度需实测。

## 本次修改

- 用一个静态 10240 字节文字行缓冲，通过课程 lcd_ram_draw_string 绘制，再整行传送 LCD，替换运行时逐像素绘字。
- 第四行增加 P（人员参考点在所选轴上的百分比）和 DT（连续采集完成的时间间隔，毫秒）。DT>350 ms 时该行红色；多人或无人时 P 显示 --。
- 双线从第 64 行开始画，给四行状态文字留空间。
- 保留所有 core 代码和配置，不放宽阈值；静音、日志格式与计数语义不变。

## 重新测试

烧录 `dist/vision-count/greeter-count-v0.3.bin`，不要误选 v0.2。构建使用 `& '.\tools\windows\build-vision.ps1' -Target vision-count`。源码 SHA、固件校验值见同目录 manifest.json 和 SHA256SUMS.txt。保持仅一人在画面中，固定摄像头。

1. 观察 N 是否持续为 1，并记下第四行 P、DT 和第三行状态。
2. 默认 X 轴：P 明显小于 32% 才在 A 外侧，P 明显大于 68% 才在 B 外侧；不是人员框边缘越线就算越过。屏幕 P 只显示一位小数，勿用恰好边界值判断。
3. 在 P 约 20%–25% 处停留约 1 秒，看能否出现 FROM_A。
4. 在约 2 秒内缓慢经过中间区域（P 约 38%–62%），走至 P 约 75%–80%，再停留约 1 秒，观察 IN。反向再测 OUT。
5. 如果 DT 经常超过 350 ms，先记录实际范围，不把移动更慢或延长站立当作修复；该条件会持续打断轨迹。若 DT 小于 350 ms 且 P 明显在外侧却仍 WAIT_ORIGIN，保存完整 frame/state 日志进一步排查漏检、位置关联等问题。

请回传：P、DT 的典型数值与波动范围、N 是否闪烁、状态变化、IN/OUT 变化；有条件时保留从复位开始的完整串口日志。

本版是诊断与显示性能改进，不代表已经解决实板零计数。编译验证与实际显示效果、帧率及计数结果分别记录；板卡需人工重新烧录验证。
