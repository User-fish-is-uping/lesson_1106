# 核心模块接入说明

本说明对应仓库中的实际公开头文件。语义基线为接口约定 v0.2；公开头文件需与固件调用方按提交 SHA 核对。尚未进行 K210 交叉编译或实物验证。

## 构建与回放

在仓库根运行（需要 C 编译器、CMake >=3.16、Python3；无第三方 Python 依赖）：

```sh
cmake -S . -B build/host
cmake --build build/host -j2
ctest --test-dir build/host --output-on-failure
python3 tools/host/replay.py tests/data/synthetic_roundtrip.jsonl
```

正常构建包含 28 项 CTest 测试。回放默认使用 `build/host/libgreeter_replay.so`；Windows 可通过 `--library` 指定其构建得到的 DLL（需工具链导出 bridge 函数，Windows 主机回放未验证），macOS 可指定 dylib。K210 只编译 core 的两个 C 文件，不编译主机回放桥接。

回放读取 frame JSONL，通过 ctypes 调用同一份 C 实现；Python 只校验和转换数据，没有独立计数算法。非 frame kind 忽略；缺 kind、坏 JSON、缺字段、超容量、非法数值返回退出码 2 并显示行号；没有 frame 返回 3。逻辑异常输出 diagnostic 的数字错误码（对应 greeter_error_t），保留顺序处理后续帧；输出 event 及末尾 summary。

示例是 synthetic，不是真实摄像头日志：9 帧，ENTER id=1/t=600、EXIT id=2/t=1200，最终 in=1/out=1。`--reverse` 反转进入离开含义。当前回放使用默认配置，除 reverse 外不支持命令行调参；现场改阈值后应将配置与日志一起交回，扩展统一配置加载后再作同参数回放。

可选内存/未定义行为检查：

```sh
cmake -S . -B build/sanitize -DENABLE_SANITIZERS=ON
cmake --build build/sanitize -j2
ASAN_OPTIONS=detect_leaks=0 ctest --test-dir build/sanitize --output-on-failure
```

当前沙箱 LeakSanitizer 因 ptrace 不可用，因此仅关闭泄漏扫描；ASan 地址检查和 UBSan 仍开启。sanitizer 构建的 Python/ctypes 测试明确禁用，普通构建已验证此项。core 无动态内存分配。

## 板端接入

将 `core/greeter.c`、`core/audio_queue.c` 加到固件目标，include path 添加 core/；使用 SDK gnu11 或 C99，若工具链需要则链接 libm。仅从主循环调用，不要在中断调用，也不要复制第二套状态机。

1. 持有 `greeter_t` 和 `audio_queue_t` 两个实例。
2. `greeter_default_config()` → 按机位调整配置 → `greeter_init()`；`audio_queue_init(&queue,5000)`。初始化失败必须处理；失败不覆盖已有实例，禁止继续使用未初始化对象。
3. 主循环先处理清零/方向/静音控制，再传入一次推理帧。
4. `greeter_update()` 返回 true 时，event 有效、core 计数已更新；调用 `audio_queue_push()`，记录其返回结果；无论入队成功与否都不再加计数。
5. 从 `greeter_get_snapshot()` 取 LCD 和串口状态。false 不总表示故障，可表示正常未完成通行；检查 last_error。
6. 每轮 `audio_queue_peek()` 清理过期项并取队首，播放器 idle 时只尝试一次启动，用同一个采样 now_ms 调用 `audio_queue_report()`；不要先 pop 后启动。STARTED 当场消费，BUSY 保留，FAILED 首次保留、二次移除。
7. 每轮最多一次启动尝试，失败重试必须回到后续主循环；此调用纪律由 firmware 保证，core 不知道“主循环轮次”。播放结束不再消费；异步播放失败只调用 `audio_queue_report_async_failure()`。
8. 清零：greeter_reset_counts + audio_queue_clear。实际改变方向：greeter_set_reverse + audio_queue_clear。静音：audio_queue_set_muted。当前已播放的一句不强制停止。

`tools/host/integration_example.c` 是已编译的无 SDK 接入示例，不包含实际板端驱动。

## 精确边界与初始参数

- 默认线 0.35/0.65、缓冲 0.03；外侧稳定 150 ms、漏检宽限 350 ms、穿越超时 5000 ms。
- 默认二维位置关联基础容差 0.05、速度上限 2.0 个归一化单位/秒，未实板标定。比较底边中心的二维位移，允许距离=tolerance+speed×距上次实际检测秒数。
- score 严格大于阈值；框需有限、0..1、x1<x2、y1<y2。core 接到非法框清轨迹，绝不读取超容量数组。合法低分框忽略。
- 稳定到 `elapsed>=stable_ms` 确认；空帧打断端点稳定计时，短空仍保留通行候选。漏检 `elapsed>grace_ms` 清轨迹，等于宽限仍可关联。
- 穿越计时从已建立起点后首次离开原外侧开始；`elapsed>timeout_ms` 清理，此帧不作为新起点。原侧长期停留不超时。折返并在原侧重新稳定后清中间证据和穿越计时。
- 首次建立起点前的中间观测不能用于之后穿越。直接跨外侧无中间证据不计；关联合理时当前帧开始建立新起点，关联不合理时直接清轨迹并丢弃当前帧。
- 重复或倒退帧号不处理，不推进逻辑时间，记录 OLD_FRAME；同毫秒新帧可处理但不累计时间。序号有效而时间倒退时记录 TIME_BACKWARD、清轨迹、消耗帧号并以该时间作为恢复基准，当前帧不建立起点。
- LOST 保留短漏检轨迹，AMBIGUOUS 清轨迹；恢复需要重新满足起点规则。candidate_direction 为 +1=A→B、-1=B→A、0=无起点，是几何方向，不随 reverse 翻转；事件类型随 reverse 翻转。
- `greeter_update` 输出事件仅返回 true 时有效；无事件时不改输出对象。初始化、参数失败和错误枚举见头文件。控制清轨迹但保留最后输入序号/时钟及事件编号。
- 配置要求外侧非空，中间严格正宽；稳定/宽限均大于 0，穿越时限大于二者；速度有限且>0、容差[0,1]、score阈值[0,1]。非法配置不写入实例。
- 队列 `age>=max_wait_ms` 过期；未来事件或服务时间倒退拒绝，不执行无符号减法回绕。已过期新事件返回 AUDIO_EMPTY 并累计 expired。
- 合法新 ID 即使因静音、满或过期丢弃，也提升去重水位；`id<=watermark` 拒绝。clear/mute 不重置水位和统计。
- 所有队列累计统计饱和；通行计数或 ID 到 UINT64_MAX 时拒绝继续生成事件并报告 OVERFLOW，不回绕。重新上电必须重新 init。

完成：状态机、固定队列、确定性主机测试、播放忙时排队模拟、JSONL 回放、无 SDK 接入示例。

待板端验证：真实人员检测、摄像头方向与帧率标定、TF/WAV、DMA 并发、交叉编译、烧录与实物正确率。无真实日志或人工标注，不提供现场准确率，不把 synthetic 回放当实板证据。
