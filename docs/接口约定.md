## 1. 目录与责任

以下实现目录将在开发中建立。

```text
core/                  可移植 C 代码
  greeter.h            配置、输入、事件、状态快照与公开函数
  greeter.c            单人关联及双线状态机
  audio_queue.h/.c     有界语音事件队列
tests/                 主机上的确定性测试
tools/host/            检测日志回放与结果汇总
firmware/              K210 固件代码
  main.c               初始化和主循环
  vision_adapter.*     KPU 输出到统一帧输入
  audio_player.*       TF/I2S/DMA、播放完成及错误回调
  ui.*                 LCD 与按键
  board_config.h       硬件资源统一配置
tools/windows/         桌面编译和打包脚本
docs/                  双方共享的计划、接口与交接证据
```

core 的公共头文件只依赖标准 C 类型。模型句柄、SDK 类型、GPIO、文件系统、睡眠函数和真实音频驱动由 firmware 层负责。时间由调用方传入，便于主机回放。

core 使用 C99、无动态分配、无 SDK 依赖，由单线程主循环调用；中断不得直接调用 core。桌面课程 SDK 默认以 gnu11 编译，接受这里的 C99 子集。云端主机目标应显式要求 C99。

## 2. 配置

| 字段语义 | 初始版本建议值 | 说明 |
|---|---|---|
| 运动主轴 | X | 现场确认后可改 Y |
| line_a、line_b | 0.35、0.65 | 归一化位置，line_a 小于 line_b |
| hysteresis | 0.03 | 线附近的缓冲带 |
| outer_stable_ms | 150 | 起点、终点外侧连续稳定时间 |
| lost_grace_ms | 350 | 候选轨迹可容忍的短时空检测 |
| traversal_timeout_ms | 5000 | 候选穿越超时后清理 |
| confidence_threshold | 0.50 | 与检测适配层约定一致 |
| reverse_direction | false | 默认 A 侧到 B 侧为进入 |
| 位置关联门限 | 由帧间隔和可调速度上限决定 | 初始版本明确实现方法，保留配置 |

这些值用于开始测试。实际阈值由实板帧间隔、机位和通行速度决定。配置校验处理非法线顺序、越界、负值和超时关系。

## 3. 每帧输入

greeter_frame_t 至少包含以下信息。

| 信息 | 语义 |
|---|---|
| sequence_id | uint64_t 单调增长的帧序号，重复输入不产生重复事件 |
| now_ms | uint64_t 单调毫秒时间，用同一时钟记录事件和播放 |
| valid | 本帧视觉结果是否有效，推理或采集失败时为 false |
| person_count | 置信筛选后的人数，范围 0 到 10 |
| truncated | 检测列表达到或超过容量时标为歧义，由适配层保守判断 |
| persons[10] | 人员框 x1、y1、x2、y2 与 score |

坐标统一为摄像头实际推理画面上的 0 到 1 归一化坐标。LCD 镜像与旋转由桌面侧适配，确保屏幕线和逻辑线表示同一位置。适配层保留现成模型的 person 类别索引 14，并依据实际模型标签确认。

课程物体检测例程的 region_layer 输出对应 320×240 图像，不使用 320×256 推理缓冲尺寸归一化。首版桌面适配层将浮点框边界先裁剪至 x=[0,319]、y=[0,239]，再除以 319.0f、239.0f，过滤非有限数、退化框，并保留 class_id==14 且 score>0.50 的框；core 的置信度判断与此保持一致。原例程先转无符号坐标存在负边界处理风险，桌面适配时修正。实体左右、传感器镜像和 LCD 朝向尚待实板确认；core 不内置镜像逻辑。

选定框的位置参考点默认采用底边中心。运动主轴选择 X 时使用其 X 坐标，选择 Y 时使用其 Y 坐标。没有检测到人时 valid=true、person_count=0。驱动故障与空画面分开处理。

## 4. 事件与快照

只有确认的通行生成 greeter_event_t，字段包含 event_id、type、timestamp_ms。type 取 ENTER 或 EXIT。event_id 在一次上电会话内递增，清零计数时保持编号递增。

一次 greeter_update 最多返回一个事件。事件确认时更新 core 内部计数，firmware 读取快照显示，避免多层重复加计数。音频静音、队列满或播放失败不回滚已确认的计数。

快照至少包含当前状态、进入次数、离开次数、候选方向与最后异常原因。状态能够表达 WAIT_ORIGIN、FROM_A、FROM_B、LOST、AMBIGUOUS。具体内部细分状态由核心模块实现并文档化。

建议公开函数包括 greeter_init、greeter_update、greeter_get_snapshot、greeter_reset_counts、greeter_set_reverse。实例状态采用调用方持有的结构体，避免堆分配与函数内全局单例。参数和返回类型以初始版本提交的头文件统一。

## 5. 状态机必须保持的行为

1. 初次在中间区域出现时，等待其在某一外侧建立稳定起点。
2. 起点在 A 外侧，连续跨过中间到 B 外侧并稳定后，确认 A→B。反向同理。首版必须在建立起点后、确认终点前至少观察到一帧有效且关联合理的单人中间区域结果。A 外侧定义 p<line_a-hysteresis，B 外侧定义 p>line_b+hysteresis，中间证据定义 line_a+hysteresis<=p<=line_b-hysteresis，其余为缓冲带。配置须保证中间区间非空。A/B 直接跳变且没有中间证据，不计数、清理旧候选，当前帧只能开始建立新起点，须重新满足外侧稳定时间。中间证据不能绕过位置关联校验；失效、超时、多人或重建起点时清除。
3. 停留、边线小幅抖动和未完成穿越的折返不确认事件。
4. 完成 A→B 后，B 侧成为新的稳定起点。该人若完整返回 A 侧，可再次确认反向事件。停在 B 侧保持不重复。
5. 零人短时出现只在位置关联仍合理且未超时的条件下保留候选。长期丢失、显著轨迹跳变、无效帧和时间倒退清理候选，重新等待稳定外侧。
6. 同时多人或截断结果进入歧义状态。再次出现单人后重新建立外侧起点，避免沿用前一人的半程轨迹。
7. 实际切换 reverse_direction 或清零时清理候选。桌面侧同时清空待播事件，已经播放的一句允许播完；事件编号不重置。切换方向不清除历史计数，仅影响之后的新事件。上述控制在处理下一帧和调度下一条语音前执行。

## 6. 音频队列

队列使用固定容量，建议 4 条，保存进入/离开事件而不是音频数据。到达事件后按 event_id 去重，容量满时保留已有顺序并记录新事件丢弃次数。进入映射 0:/welcome.wav，离开映射 0:/goodbye.wav。

建议最大等待时间先设 5 秒。过期策略用于避免客人离开很久后才播放欢迎语，具体值按音频时长调整。队列错误和计数错误分别统计。

桌面主循环在播放器空闲时读取队首。只有播放器成功接受并开始该文件后，才确认消费该事件。文件缺失或格式错误记录一次失败，按有限重试策略处理并最终消费失败项，允许后续项继续。忙状态保留队首。

启动结果统一表达 STARTED、BUSY、FAILED（具体 C 枚举名由头文件确定）。每事件最多两次真实启动尝试，即首次加一次重试；BUSY 不占尝试次数，重试最早在下一次主循环服务进行，且仍受 5 秒等待期限限制。第二次 FAILED 后移除并记录。STARTED 后发生的异步播放错误记录为播放失败，不将已消费事件重新入队。进入静音时清空待播队列；静音期间仍计数、记录事件，但不入播放队列，恢复不补播。静音同样允许当前一句播完，首版不实现强制中断。清队列不得重置本次上电的去重水位或错误累计数。

播放器通过可查询的 IDLE、PLAYING、ERROR 状态和完成回调供桌面服务使用。队列只做调度，不直接接触 SD、DMA、I2S 或 SDK。

音频中断与主循环共享标志需按实际 SDK 的中断模型保护。耗时文件操作安排在受控服务中。固件模块负责检查播放完成、取消和失败路径是否正确释放 DMA 与缓冲。

## 7. 日志与回放

建议每行一个 JSON 对象，首先实现以下三类。

```json
{"kind":"frame","seq":1,"t_ms":1000,"valid":true,"truncated":false,"persons":[{"x1":0.10,"y1":0.20,"x2":0.24,"y2":0.90,"score":0.85}]}
{"kind":"event","id":1,"t_ms":2400,"type":"ENTER","in":1,"out":0}
{"kind":"audio","id":1,"t_ms":2410,"status":"start","file":"welcome.wav"}
```

示例数据仅用于说明格式。串口同时输出帧间隔、空闲内存和错误摘要时可使用额外 kind。固件版本与配置在日志开始时记录。回放工具以 frame 行喂给同一 core 实现，人工标注另存为时间窗和方向。不同机器之间用同一日志和同一 core 提交比较。

## 8. 合并规则

公共头文件由固件维护方核对，按提交号冻结 v0.2。后续修改字段或函数时，交接记录先列出差异，桌面侧与调用方一起更新。双方使用不同分支，在同一批接口下并行开发。

协作目标仓库采用 User-fish-is-uping/lesson_1106，云端 cloud/core，桌面 desktop/firmware，桌面负责集成。访问方式与分支说明见开发与集成流程。仓库根目录沿用启动包的 core/、firmware/、docs/ 等结构，不增加额外嵌套目录。公共头文件由云端维护，桌面提出修订，避免双写。

核心模块可独立完成主机验证；固件还需 K210 交叉编译与实板测试，各类结果分别保留。
